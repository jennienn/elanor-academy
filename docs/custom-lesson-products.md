# 운영자 수강권 관리

`/products`에서 개인레슨, 단체반, 개인·단체 패키지를 생성하고 이름, 가격, 횟수, 유효기간(주), 수업 길이(분), 판매 상태를 수정한다. 단체반에는 요일별 시작시간을 설정한다. 패키지의 수업 길이는 개인레슨에 적용되며 단체레슨은 선택한 반의 시간표를 사용한다.

판매 중단한 수강권은 별도 탭에서 조회한다. 새로 만든 수강권은 구매 이력이 없으면 삭제할 수 있다. 기본 수강권은 과거 구매에 상품 ID가 없어 삭제하지 않는다. 삭제는 DB에서 구매 이력과 버전을 다시 확인한 뒤 단체반·시간표까지 한 트랜잭션으로 정리한다.

구매 시 상품 이름·횟수·유효기간·수업 길이와 결제금액을 저장한다. 상품 수정 및 판매 중단은 기존 구매 건을 바꾸지 않는다. 단체 시간표는 이전 행을 보존하며 기존 구매 건은 이전 시간표로 출석한다. 재등록은 최신 상품 조건을 적용한다. 개인 잔여 횟수 이월 정책은 유지한다. 단체 재등록은 기존 요일이 현재 시간표에도 있으면 미리 선택하고 운영자가 확인한다.

새 시간표가 이미 확정된 개인 예약과 겹치면 저장을 거절한다. 개인 예약은 구매 당시 수업 길이와 기존 예약의 실제 길이로 충돌을 검사한다. 이전 단체 시간표도 기존 회원 수강 기간 동안 개인 예약을 막는다. 예약 시작시간 간격과 당일 사전 예약·취소 규칙은 기존과 같다.

## 운영 반영

운영 반영 시 기존 스키마 및 적용 이력을 확인하고 `0024_custom_lesson_products.sql`, `0025_delete_unsold_products.sql`을 앱보다 먼저 적용한다. 기존 회원의 구매 조건 보존을 확인한다.

기존 상품별 정가가 저장된 곳은 없었으므로 초기 상품 가격은 기존 등록 흐름의 금액인 0원이다. 운영자가 관리 화면에서 실제 판매 가격을 설정해야 한다. 기존 결제 금액은 변경하지 않는다. 기존 예약 정책의 단체 수업 시간(kpop 20시, 다이어트 11시)은 시작시간이 비어 있는 해당 반에만 초기화한다.

기존 회원/수강권 생성 RPC와 API는 기존 호출자와의 호환을 위해 남아 있다. 사이트의 신규 등록·추가 등록·재등록은 모두 `purchase_lesson_product`를 사용하는 `/api/products/purchase`로 통일했다. 기존 API를 사용하는 외부 연동이 있다면 상품 ID·버전을 사용하는 새 경로로 전환해야 한다.

## 검증

단위 검증은 상품 입력 경계, 로컬 DB 검증은 구매 조건 보존·변경 후 재등록·판매 중단·시간표 이력·수업 길이별 예약 충돌·패키지 원자적 생성·권한을 다룬다. 브라우저 검증은 관리 화면에서 생성부터 구매·수정·재등록·판매 중단까지 실제로 진행한다. 모든 DB 테스트는 localhost Supabase에서 수행하며 생성한 ID만 정리한다.
